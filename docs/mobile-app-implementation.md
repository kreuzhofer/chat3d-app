# Mobile App Implementation Plan

Wrap the Chat3D frontend as native iOS and Android apps using Capacitor, with native push notifications via Firebase Cloud Messaging (FCM).

## Goals

1. Publish Chat3D to the Apple App Store and Google Play Store
2. Zero changes to the existing frontend (`packages/frontend/`)
3. Native push notifications as an alternative to Web Push (both coexist)
4. Remote URL mode — the app loads the deployed frontend, no asset bundling

## Architecture Overview

```
┌─────────────────────────────────────────────────────────────┐
│                     Existing (unchanged)                     │
│                                                              │
│  Browser ──► Web Push (VAPID) ──► Service Worker ──► OS      │
│  Browser ──► SSE ──► In-app UI                               │
│                                                              │
├─────────────────────────────────────────────────────────────┤
│                     New (Capacitor shell)                     │
│                                                              │
│  Mobile App ──► FCM (APNs/Android) ──► Native notification   │
│  Mobile App ──► SSE (via WebView) ──► In-app UI              │
│                                                              │
├─────────────────────────────────────────────────────────────┤
│                     Backend (small additions)                 │
│                                                              │
│  PushNotificationService.sendToUser()                        │
│    ├── type: 'web'  → web-push npm (existing)                │
│    └── type: 'fcm'  → firebase-admin SDK (new)               │
│                                                              │
│  push_subscriptions table                                    │
│    ├── existing web-push columns (endpoint, p256dh, auth)    │
│    └── new columns: type, fcm_token                          │
└─────────────────────────────────────────────────────────────┘
```

## Phase 1: Capacitor Shell (Mobile App)

### 1.1 Create the mobile package

```
packages/mobile/
  capacitor.config.ts
  package.json
  ios/                  ← generated by `npx cap add ios`
  android/              ← generated by `npx cap add android`
```

### 1.2 Initialize Capacitor

```bash
mkdir packages/mobile && cd packages/mobile
npm init -y
npm install @capacitor/core @capacitor/cli
npx cap init "Chat3D" "com.chat3d.app" --web-dir=../frontend/dist
```

### 1.3 Configure remote URL mode

`capacitor.config.ts`:
```typescript
import type { CapacitorConfig } from "@capacitor/cli";

const config: CapacitorConfig = {
  appId: "com.chat3d.app",
  appName: "Chat3D",
  // Load the deployed frontend directly — no local bundling
  server: {
    url: "https://your-production-url.com",
    cleartext: false,  // HTTPS only
  },
  // iOS-specific settings
  ios: {
    contentInset: "automatic",  // handle safe areas (notch, dynamic island)
    scheme: "Chat3D",
  },
  // Android-specific settings
  android: {
    allowMixedContent: false,  // HTTPS only
  },
};

export default config;
```

> **Note:** `server.url` makes Capacitor load a remote URL in the WebView instead of local assets. This means the app is always up-to-date without requiring app store updates for frontend changes.

### 1.4 Add platforms

```bash
npx cap add ios
npx cap add android
```

### 1.5 App assets

Create app icons and splash screens. Capacitor expects:
- `resources/icon.png` — 1024x1024 app icon (no transparency for iOS)
- `resources/splash.png` — 2732x2732 splash screen

Use `@capacitor/assets` to generate all required sizes:
```bash
npm install -D @capacitor/assets
npx capacitor-assets generate
```

### 1.6 Build and test locally

```bash
# iOS (requires macOS + Xcode)
npx cap open ios
# Build and run on simulator from Xcode

# Android (requires Android Studio)
npx cap open android
# Build and run on emulator from Android Studio
```

### 1.7 WebView considerations

- **JWT/localStorage:** Works in Capacitor's WKWebView (iOS) and WebView (Android) — no changes needed
- **SSE (EventSource):** Works in WebView — real-time in-app updates continue working
- **Service Worker:** Not supported in Capacitor WebView — this is fine because native push replaces it
- **Safe areas / notch:** Capacitor's `contentInset: "automatic"` handles this, but verify visually. If CSS tweaks are needed, they can be done via Capacitor's local CSS injection (no changes to main frontend)
- **Cookie/storage persistence:** WKWebView persists localStorage across app launches by default

### 2.2 Capacitor push notification plugin

```bash
cd packages/mobile
npm install @capacitor/push-notifications
npx cap sync
```

### 2.3 Mobile app push registration

Create a small TypeScript module that runs at app startup (injected via Capacitor plugin, not in the main frontend):

```typescript
// packages/mobile/src/push-setup.ts
import { PushNotifications } from "@capacitor/push-notifications";
import { Capacitor } from "@capacitor/core";

export async function initNativePush(jwtToken: string, backendUrl: string) {
  if (!Capacitor.isNativePlatform()) return;

  // Request permission
  const permission = await PushNotifications.requestPermissions();
  if (permission.receive !== "granted") return;

  // Register with APNs/FCM
  await PushNotifications.register();

  // Listen for registration success — sends FCM token to backend
  PushNotifications.addListener("registration", async (token) => {
    await fetch(`${backendUrl}/api/push/subscribe`, {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        Authorization: `Bearer ${jwtToken}`,
      },
      body: JSON.stringify({
        type: "fcm",
        token: token.value,
      }),
    });
  });

  // Handle notification received while app is open
  PushNotifications.addListener("pushNotificationReceived", (notification) => {
    // Optionally show in-app toast or badge update
    console.log("Push received in foreground:", notification);
  });

  // Handle notification tap (app was in background)
  PushNotifications.addListener("pushNotificationActionPerformed", (action) => {
    const url = action.notification.data?.url;
    if (url) {
      // Navigate WebView to the deep link URL
      window.location.href = url;
    }
  });
}
```

> **Challenge:** The JWT token lives inside the WebView (localStorage), but Capacitor plugins run in native context. Options to bridge this:
>
> **Option A (Recommended):** Use a Capacitor custom plugin or `@capacitor/preferences` to share the JWT between WebView and native context. The WebView stores the token via Capacitor Preferences after login, and the native push setup reads it from there.
>
> **Option B:** Inject a small script into the WebView that listens for a custom event from the native side, retrieves the JWT from localStorage, and passes it back via `Capacitor.Plugins`.
>
> **Option C:** Add a minimal bridge page (e.g., `/mobile-bridge`) to the frontend that the native app loads first to extract the JWT. This requires a tiny frontend addition but keeps it clean.
>
> Decide on the bridging approach during implementation. Option A is cleanest.

## Phase 3: Backend Changes

### 3.1 Database migration — extend push_subscriptions

Add a `type` column and `fcm_token` column. Make web-push-specific columns nullable.

**Prisma schema change:**
```prisma
model PushSubscription {
  id        String   @id @default(dbgenerated("gen_random_uuid()")) @db.Uuid
  userId    String   @map("user_id") @db.Uuid
  type      String   @default("web") @db.VarChar(10)  // "web" | "fcm"
  endpoint  String?  @db.Text      // web push only (was required)
  p256dh    String?  @db.Text      // web push only (was required)
  auth      String?  @db.Text      // web push only (was required)
  fcmToken  String?  @map("fcm_token") @db.Text  // FCM device token (new)
  createdAt DateTime @default(now()) @map("created_at") @db.Timestamptz()

  user User @relation(fields: [userId], references: [id], onDelete: Cascade, onUpdate: NoAction)

  @@unique([userId, endpoint])       // existing — for web push dedup
  @@unique([userId, fcmToken])       // new — for FCM dedup
  @@index([userId], map: "idx_push_subscriptions_user_id")
  @@map("push_subscriptions")
}
```

**Migration SQL:**
```sql
ALTER TABLE push_subscriptions
  ADD COLUMN type VARCHAR(10) NOT NULL DEFAULT 'web',
  ADD COLUMN fcm_token TEXT,
  ALTER COLUMN endpoint DROP NOT NULL,
  ALTER COLUMN p256dh DROP NOT NULL,
  ALTER COLUMN auth DROP NOT NULL;

CREATE UNIQUE INDEX idx_push_subscriptions_user_fcm
  ON push_subscriptions (user_id, fcm_token)
  WHERE fcm_token IS NOT NULL;
```

### 3.3 Extend PushNotificationService

Changes to `packages/backend/src/services/push-notification.service.ts`:

```typescript
import * as admin from "firebase-admin";

class PushNotificationService {
  private initialized = false;
  private fcmInitialized = false;

  // ... existing isEnabled(), getPublicKey(), ensureInitialized() unchanged ...

  /**
   * Check if FCM is configured.
   */
  isFcmEnabled(): boolean {
    return !!process.env.GOOGLE_APPLICATION_CREDENTIALS;
  }

  /**
   * Initialize Firebase Admin SDK (idempotent).
   */
  private ensureFcmInitialized(): void {
    if (this.fcmInitialized || !this.isFcmEnabled()) return;
    admin.initializeApp({
      credential: admin.credential.applicationDefault(),
    });
    this.fcmInitialized = true;
  }

  /**
   * Save an FCM subscription for a user.
   */
  async subscribeFcm(userId: string, token: string): Promise<void> {
    await prisma.pushSubscription.upsert({
      where: { userId_fcmToken: { userId, fcmToken: token } },
      create: { userId, type: "fcm", fcmToken: token },
      update: { fcmToken: token },
    });
    logger.info({ userId }, "FCM subscription saved");
  }

  /**
   * Remove an FCM subscription for a user.
   */
  async unsubscribeFcm(userId: string, token: string): Promise<boolean> {
    try {
      await prisma.pushSubscription.delete({
        where: { userId_fcmToken: { userId, fcmToken: token } },
      });
      logger.info({ userId }, "FCM subscription removed");
      return true;
    } catch {
      return false;
    }
  }

  /**
   * Send a push notification to all subscriptions (web + FCM) for a user.
   */
  async sendToUser(userId: string, payload: PushPayload): Promise<number> {
    const subs = await prisma.pushSubscription.findMany({
      where: { userId },
      select: { id: true, type: true, endpoint: true, p256dh: true, auth: true, fcmToken: true },
    });

    if (subs.length === 0) return 0;

    let sent = 0;

    for (const sub of subs) {
      if (sub.type === "web") {
        // Existing web-push logic (unchanged)
        sent += await this.sendWebPush(sub, payload);
      } else if (sub.type === "fcm") {
        // New FCM logic
        sent += await this.sendFcmPush(sub, payload);
      }
    }

    if (sent > 0) logger.info({ userId, sent, total: subs.length }, "push notifications sent");
    return sent;
  }

  private async sendWebPush(sub: { id: string; endpoint: string | null; p256dh: string | null; auth: string | null }, payload: PushPayload): Promise<number> {
    if (!this.isEnabled() || !sub.endpoint || !sub.p256dh || !sub.auth) return 0;
    this.ensureInitialized();

    try {
      await webpush.sendNotification(
        { endpoint: sub.endpoint, keys: { p256dh: sub.p256dh, auth: sub.auth } },
        JSON.stringify(payload)
      );
      return 1;
    } catch (error: unknown) {
      const statusCode = (error as { statusCode?: number }).statusCode;
      if (statusCode === 404 || statusCode === 410) {
        await prisma.pushSubscription.delete({ where: { id: sub.id } });
        logger.info({ subscriptionId: sub.id }, "removed expired push subscription");
      } else {
        logger.error({ err: error instanceof Error ? error : new Error(String(error)), subscriptionId: sub.id }, "push notification failed");
      }
      return 0;
    }
  }

  private async sendFcmPush(sub: { id: string; fcmToken: string | null }, payload: PushPayload): Promise<number> {
    if (!this.isFcmEnabled() || !sub.fcmToken) return 0;
    this.ensureFcmInitialized();

    try {
      await admin.messaging().send({
        token: sub.fcmToken,
        notification: { title: payload.title, body: payload.body },
        data: { tag: payload.tag, url: payload.url || "/" },
        // APNs-specific config for iOS
        apns: {
          payload: { aps: { sound: "default", badge: 1 } },
        },
        // Android-specific config
        android: {
          priority: "high",
          notification: { sound: "default", clickAction: "FCM_PLUGIN_ACTIVITY" },
        },
      });
      return 1;
    } catch (error: unknown) {
      const code = (error as { code?: string }).code;
      if (code === "messaging/registration-token-not-registered") {
        await prisma.pushSubscription.delete({ where: { id: sub.id } });
        logger.info({ subscriptionId: sub.id }, "removed expired FCM token");
      } else {
        logger.error({ err: error instanceof Error ? error : new Error(String(error)), subscriptionId: sub.id }, "FCM notification failed");
      }
      return 0;
    }
  }
}
```

### 3.4 Extend push routes

Changes to `packages/backend/src/routes/push.routes.ts`:

```typescript
/**
 * POST /api/push/subscribe
 * Register a push subscription (web or FCM) for the authenticated user.
 *
 * Web Push body:  { type?: "web", endpoint, keys: { p256dh, auth } }
 * FCM body:       { type: "fcm", token }
 */
pushRouter.post("/subscribe", async (req, res) => {
  const authUser = req.authUser;
  if (!authUser) { res.status(401).json({ error: "Authentication required" }); return; }

  const { type = "web" } = req.body;

  if (type === "fcm") {
    const { token } = req.body;
    if (!token) {
      res.status(400).json({ error: { code: "VALIDATION_ERROR", message: "token is required for FCM subscriptions." } });
      return;
    }
    await pushNotificationService.subscribeFcm(authUser.id, token);
    res.status(201).json({ subscribed: true });
    return;
  }

  // Existing web-push flow (unchanged)
  const { endpoint, keys } = req.body;
  if (!endpoint || !keys?.p256dh || !keys?.auth) {
    res.status(400).json({ error: { code: "VALIDATION_ERROR", message: "endpoint, keys.p256dh, and keys.auth are required." } });
    return;
  }
  if (!pushNotificationService.isEnabled()) {
    res.status(404).json({ error: { code: "NOT_CONFIGURED", message: "Push notifications are not configured." } });
    return;
  }
  await pushNotificationService.subscribe(authUser.id, { endpoint, keys: { p256dh: keys.p256dh, auth: keys.auth } });
  res.status(201).json({ subscribed: true });
});

/**
 * POST /api/push/unsubscribe
 * Remove a push subscription (web or FCM).
 *
 * Web Push body:  { type?: "web", endpoint }
 * FCM body:       { type: "fcm", token }
 */
pushRouter.post("/unsubscribe", async (req, res) => {
  const authUser = req.authUser;
  if (!authUser) { res.status(401).json({ error: "Authentication required" }); return; }

  const { type = "web" } = req.body;

  if (type === "fcm") {
    const { token } = req.body;
    if (!token) {
      res.status(400).json({ error: { code: "VALIDATION_ERROR", message: "token is required." } });
      return;
    }
    const removed = await pushNotificationService.unsubscribeFcm(authUser.id, token);
    res.json({ removed });
    return;
  }

  // Existing web-push flow (unchanged)
  const { endpoint } = req.body;
  if (!endpoint) {
    res.status(400).json({ error: { code: "VALIDATION_ERROR", message: "endpoint is required." } });
    return;
  }
  const removed = await pushNotificationService.unsubscribe(authUser.id, endpoint);
  res.json({ removed });
});
```

### 3.5 Updated isEnabled check

The `GET /api/push/status` endpoint should reflect both push types:

```typescript
pushRouter.get("/status", async (req, res) => {
  const authUser = req.authUser;
  if (!authUser) { res.status(401).json({ error: "Authentication required" }); return; }

  const webEnabled = pushNotificationService.isEnabled();
  const fcmEnabled = pushNotificationService.isFcmEnabled();

  if (!webEnabled && !fcmEnabled) {
    res.json({ enabled: false, subscriptionCount: 0 });
    return;
  }

  const subscriptions = await pushNotificationService.getSubscriptions(authUser.id);
  res.json({ enabled: true, webEnabled, fcmEnabled, subscriptionCount: subscriptions.length });
});
```

## Phase 4: App Store Submission

### 4.1 Apple App Store

**Prerequisites:**
- Apple Developer Program membership ($99/year)
- Xcode with valid signing certificate and provisioning profile
- App Store Connect account set up

**Steps:**
1. In Xcode, set the correct bundle ID (`com.chat3d.app`), version, and build number
2. Add the Push Notifications capability in Signing & Capabilities
3. Add the Background Modes capability → Remote notifications
4. Archive the app: Product → Archive
5. Upload to App Store Connect via Xcode Organizer
6. Fill in App Store listing: screenshots, description, privacy policy URL, support URL
7. Submit for review

**App Store Review considerations:**
- Apple rejects pure WebView wrappers (Guideline 4.2). Native push notifications provide the required native functionality
- Ensure the app provides value beyond what Safari can do — push notifications + app icon + full-screen experience qualify
- Include a privacy policy that covers push notification data collection
- If rejected, consider adding: haptic feedback, share sheet integration, or biometric auth (all available as Capacitor plugins with minimal effort)

### 4.2 Google Play Store

**Prerequisites:**
- Google Play Developer account ($25 one-time)
- Android Studio for building the release APK/AAB

**Steps:**
1. Generate a signed release bundle: Build → Generate Signed Bundle/APK → Android App Bundle
2. Create the app listing in Google Play Console
3. Upload the AAB to the Production track (or Internal Testing first)
4. Fill in store listing: screenshots, description, privacy policy
5. Complete the content rating questionnaire and data safety form
6. Submit for review

**Google Play considerations:**
- Google is generally more lenient with WebView apps than Apple
- The data safety form must declare push notification token collection
- Target the latest Android SDK version as required by Google Play policies

## Implementation Order

1. **Phase 1** (Capacitor shell) — Get the app running in iOS Simulator and Android Emulator with remote URL. Verify login, chat, SSE, and 3D model viewing all work in the WebView.

2. **Phase 3** (Backend changes) — Run the Prisma migration and extend the push service/routes. Deploy backend. Verify existing web push still works.

3. **Phase 2** (Native push) — Add the Capacitor push plugin, set up Firebase, implement the JWT bridging and FCM token registration. Test push notifications end-to-end on both platforms.

4. **Phase 4** (App Store submission) — Prepare store listings, screenshots, and submit for review.

> **Note:** Phase 3 (backend) is listed before Phase 2 (native push setup) because the backend endpoints must exist before the mobile app can register FCM tokens. However, Phase 1 (basic Capacitor shell) can be developed and tested independently.
