### Iterate path

The Phase 2 mechanism *fires* now, but the agent is over-penalized by it. Likely follow-ups:

1. **Investigate `32b6c670` orchestration bypass** — why did the multi-agent loop fall through to `code_only` with null `sub_agent_verifications`? This is a critical orchestration regression.
2. **Pi Zero `05066df7` assertion-fail cascade** — the assertion harness fired 3 hard FAILs that took precedence over the agent's own 7+ self-score. Either the assertions are too strict for the agent's actual output, or the agent is genuinely submitting worse code. The visual-FAIL reasoning shows the VLM admits the renders are "qualitatively consistent" but flags low resolution, which means the visual signal isn't actually carrying load here — the code-review FAIL is dominant.
3. **Single-agent collateral damage (-0.40)** — Phase 2 should not touch single-agent runs, but they regressed nonetheless. Top losers: `00d1eb27` (-2.6), `645de13c` (-2.0), `10024302` (-1.9), `0636174a` (-1.0). Worth checking whether changes outside the gate (e.g., codegen prompt, assertion threshold) leaked into single-agent.
4. **Visual VLM resolution complaint** — the VLM cites "very small, low-resolution" repeatedly. Check the actual PNG dimensions being sent and whether upscaling or fewer viewport crops would help.

### Cost

Not measured in this run, but the multi-agent loop with a functional gate calls the VLM more often than v6 did (since v6 was returning empty). Worth measuring before iterating further.
